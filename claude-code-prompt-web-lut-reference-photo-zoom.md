## 2. Click-to-zoom — Settings → LUTs page only

**Not the `LutPicker` dropdown.** Its rows already select a LUT on
click (`renderItem` in `apps/web/components/review/lut-picker.tsx`
calls `onSelect(lut.id)`) — adding a second click-to-zoom behavior on
the same clickable row is a genuine interaction conflict, not just
visual clutter. Only build this for `LutRow` in
`apps/web/app/(dashboard)/settings/luts/page.tsx`, where the thumbnail
has no existing click handler to collide with.

- Clicking a `LutRow`'s thumbnail opens a larger view — a modal/lightbox
  is fine, match this app's existing dialog patterns
  (`ConfirmDialog` or similar already in use on this page) rather than
  introducing a new one.
- **Re-render at the larger target size**, don't upscale the small
  cached thumbnail PNG (`THUMBNAIL_WIDTH`/`HEIGHT` in
  `lut-thumbnail.ts`) — that would just look blurry. Parameterize
  `renderLutThumbnail`'s render dimensions (or add a sibling function
  that shares the cube-cache/GL-context/concurrency machinery already
  built in `lut-thumbnail.ts`, rather than duplicating that plumbing)
  so the zoomed view gets a crisp render at something like 480×320 (or
  whatever matches the source image's actual aspect ratio after change
  #1).
- Cache the large render the same way the thumbnail is cached (module-
  level `Map`), so re-opening the same LUT's zoom doesn't re-render
  from scratch every time within a session.
